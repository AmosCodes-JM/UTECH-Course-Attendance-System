## Conventions

**Requests** are JSON (`Content-Type: application/json`). Bodies are validated with Zod and are **strict**: unknown fields are rejected with `400` (this is how the API refuses client-supplied timestamps, roles or user IDs). IDs in URLs must be positive integers.

**Successful responses**

```json
{ "success": true, "data": { "...": "..." } }
```

**Error responses** - raw database errors are never returned:

```json
{
  "success": false,
  "message": "Attendance has already been recorded for this session.",
  "code": "ALREADY_CHECKED_IN",
  "errors": [{ "field": "email", "message": "Enter a valid email address" }]
}
```

`errors` is only present for validation failures.

**Timestamps** are ISO 8601 UTC strings generated by the server/database. **Dates** are `YYYY-MM-DD`; date filters use `APP_TIMEZONE` (default `America/Jamaica`).

**Semester slots** are `"1"`, `"2"`, `"YEAR"` (year-long, both semesters) or `"EITHER"` (either semester).

## Authentication model

|                   | Lecturers                        | Administrators                                            |
| ----------------- | -------------------------------- | --------------------------------------------------------- |
| Login page        | `/lecturer/login`                | `/admin/login`                                            |
| Login endpoint    | `POST /api/auth/lecturer/login`  | `POST /api/auth/admin/login`                              |
| Role accepted     | `LECTURER` only                  | `ADMIN` only                                              |
| Logout            | `POST /api/auth/lecturer/logout` | `POST /api/auth/admin/logout`                             |
| Profile           | `GET /api/auth/lecturer/me`      | `GET /api/auth/admin/me`                                  |
| Self-registration | `POST /api/lecturers`            | none (seed, `npm run create-admin`, or an existing admin) |

- Sessions use an **HTTP-only cookie** named `sams.sid` (`SameSite=Lax`, `Secure` in production). Session data lives in PostgreSQL.
- The session ID is **regenerated** on every login; logout **destroys** the server-side session and clears the cookie.
- Every protected request reloads the user from the database; a deleted account or changed role ends the session (`401 SESSION_INVALID`).
- **CSRF:** login and `me` responses include a `csrfToken`. Every authenticated `POST`, `PATCH` or `DELETE` must send it in the `X-CSRF-Token` header, otherwise `403 CSRF_INVALID`. In addition, any state-changing request whose `Origin` header is not one of `CLIENT_URL` is refused with `403 ORIGIN_NOT_ALLOWED`.
- Browsers must send cookies: `fetch(url, { credentials: 'include' })`.

Access labels below: **Public**, **Lecturer** (signed in through the lecturer login), **Admin** (signed in through the administrator login). A lecturer calling an admin endpoint, or an admin calling a lecturer endpoint, gets `403 WRONG_ROLE`; without a session the response is `401 UNAUTHENTICATED`.

## Lecturer authentication

### `POST /api/auth/lecturer/login` - Public, rate-limited

Body:

```json
{ "identifier": "lecturer1@example.com", "password": "Lecturer@12345" }
```

`identifier` is an email address or work ID (case-insensitive).

`200`:

```json
{
  "success": true,
  "data": {
    "user": {
      "id": 2,
      "workId": "LEC001",
      "firstName": "Morgan",
      "lastName": "Ellis",
      "email": "lecturer1@example.com",
      "role": "LECTURER"
    },
    "csrfToken": "64 hex characters",
    "redirectTo": "/lecturer"
  }
}
```

Errors: `400 VALIDATION_ERROR`; `401 INVALID_CREDENTIALS` (same message for unknown account and wrong password); `403 WRONG_LOGIN_PORTAL` (an administrator tried to sign in here - no session is created); `429 RATE_LIMITED` (too many failed attempts).

### `POST /api/auth/lecturer/logout` - Lecturer, CSRF

`200 { "success": true, "data": { "redirectTo": "/lecturer/login" } }` - the session is destroyed and the cookie cleared.

### `GET /api/auth/lecturer/me` - Lecturer

`200 { "data": { "user": { ... }, "csrfToken": "..." } }`

## Administrator authentication

### `POST /api/auth/admin/login` - Public, rate-limited

Same body and response shape as the lecturer login, with `"redirectTo": "/admin"`. A lecturer account gets `403 WRONG_LOGIN_PORTAL`.

### `POST /api/auth/admin/logout` - Admin, CSRF

`200 { "data": { "redirectTo": "/admin/login" } }`

### `GET /api/auth/admin/me` - Admin

`200 { "data": { "user": { ... }, "csrfToken": "..." } }`

## Session status

### `GET /api/auth/session` - Public

Used by the React app on load to decide where to send the user.

```json
{ "success": true, "data": { "authenticated": true, "user": { "role": "LECTURER", "...": "..." }, "csrfToken": "..." } }
```

or `{ "authenticated": false, "user": null, "csrfToken": null }`.

## Catalog (public)

### `GET /api/programs`

```json
{
  "success": true,
  "data": [
    {
      "id": 1,
      "name": "BSc Computing",
      "major": "Computer Science",
      "displayName": "BSc Computing – Computer Science",
      "school": { "id": 1, "code": "SCIT", "name": "School of Computing & Information Technology" }
    }
  ]
}
```

### `GET /api/programs/:id/modules?semester=current`

`semester` is `current` (default) or `all`. With `current`, only modules whose slot is offered in the current semester are returned (slot `1` or `2` matching the term, plus `YEAR` and `EITHER`).

```json
{
  "success": true,
  "data": {
    "program": { "id": 1, "displayName": "BSc Computing – Computer Science", "...": "..." },
    "semester": {
      "id": 3,
      "academicYear": "2026/2027",
      "term": 1,
      "startDate": "2026-09-01",
      "endDate": "2026-12-31",
      "label": "2026/2027 Semester 1"
    },
    "modules": [
      {
        "id": 41,
        "code": "ENS3001",
        "name": "Environmental Studies",
        "credits": 3,
        "level": 1,
        "semesterSlot": "1",
        "choiceGroup": "ENS3001/MEE2003"
      }
    ]
  }
}
```

Errors: `404 PROGRAM_NOT_FOUND`; `409 NO_ACTIVE_SEMESTER` (no semester covers today, only for `semester=current`).

### `GET /api/semesters/current`

`200 { "data": { "semester": { ... } } }` - `semester` is `null` between semesters.

## Students (public)

### `POST /api/students` - register a student (rate-limited)

```json
{
  "firstName": "Nia",
  "lastName": "Newton",
  "idNumber": "2000123",
  "email": "nia.newton@students.example.com",
  "programId": 1,
  "moduleIds": [12, 40]
}
```

Rules: all fields required; email valid; `idNumber` 4–20 letters/digits/dashes (stored upper-case); ID number and email unique (email case-insensitive); programme must exist; every module must belong to the programme **and** be offered in the current semester; no two modules from the same either/or choice group. The student and their enrollments for the current semester are created in one transaction.

`201`:

```json
{
  "success": true,
  "data": {
    "student": { "idNumber": "2000123", "firstName": "Nia", "lastName": "Newton", "program": { "...": "..." } },
    "semester": { "label": "2026/2027 Semester 1", "...": "..." },
    "enrolledModuleCount": 2
  }
}
```

Errors: `400 VALIDATION_ERROR`, `400 INVALID_PROGRAM`, `400 MODULE_NOT_OFFERED`, `400 EITHER_OR_CONFLICT`, `409 DUPLICATE_ID_NUMBER`, `409 DUPLICATE_EMAIL`, `409 NO_ACTIVE_SEMESTER`, `429 RATE_LIMITED`.

### `GET /api/students/:idNumber/open-courses` - kiosk lookup (rate-limited)

Returns the student's name and programme (never their email) and the enrolled courses that have an **open** class session in the same semester as the enrollment.

```json
{
  "success": true,
  "data": {
    "student": {
      "idNumber": "2600001",
      "firstName": "Alex",
      "lastName": "Sample",
      "program": { "displayName": "BSc Computing – Computer Science", "...": "..." }
    },
    "courses": [
      {
        "sessionId": 7,
        "moduleId": 12,
        "code": "CIT2004",
        "name": "Object-Oriented Programming",
        "lecturer": "Morgan Ellis",
        "openedAt": "2026-11-26T02:19:40.123Z",
        "alreadyCheckedIn": false,
        "checkedInAt": null
      }
    ]
  }
}
```

Errors: `400 VALIDATION_ERROR` (malformed ID), `404 STUDENT_NOT_FOUND`.

## Attendance

### `POST /api/attendance` - check in (Public, rate-limited)

```json
{ "idNumber": "2600001", "sessionId": 7 }
```

Only these two fields are accepted - a `checkedInAt` (or any other) field is rejected with `400`. The check-in time is generated by PostgreSQL.

Checks, in order: student exists → session exists → session is open → student enrolled in the session's module for the session's semester → no existing record → insert. The final guard is the database constraint `UNIQUE (session_id, student_id)`.

`201`:

```json
{
  "success": true,
  "data": {
    "attendanceId": 15,
    "checkedInAt": "2026-11-26T02:20:03.511Z",
    "course": { "code": "CIT2004", "name": "Object-Oriented Programming" }
  }
}
```

Errors:

| Status | Code                                      | When                                                                                                                              |
| ------ | ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 400    | `VALIDATION_ERROR`                        | Missing/invalid fields, or extra fields such as `checkedInAt`                                                                     |
| 404    | `STUDENT_NOT_FOUND` / `SESSION_NOT_FOUND` | Unknown ID number or session                                                                                                      |
| 409    | `SESSION_CLOSED`                          | The lecturer has closed the session                                                                                               |
| 403    | `NOT_ENROLLED`                            | Student not enrolled in that module this semester                                                                                 |
| 409    | `ALREADY_CHECKED_IN`                      | `"Attendance has already been recorded for this session."` - also returned when simultaneous duplicates hit the unique constraint |
| 429    | `RATE_LIMITED`                            | Too many requests from this IP                                                                                                    |

### `GET /api/attendance?moduleId=&date=` - Lecturer

`moduleId` is required; `date` (`YYYY-MM-DD`) is optional - omit it for all dates. The lecturer must be assigned to the module (`403 NOT_YOUR_COURSE` otherwise), and only sessions **they** opened are included.

```json
{
  "success": true,
  "data": {
    "module": { "id": 12, "code": "CIT2004", "name": "Object-Oriented Programming" },
    "date": "2026-11-25",
    "timezone": "America/Jamaica",
    "total": 1,
    "records": [
      {
        "id": 15,
        "studentIdNumber": "2600001",
        "firstName": "Alex",
        "lastName": "Sample",
        "checkedInAt": "2026-11-26T02:20:03.511Z",
        "sessionId": 7,
        "sessionOpenedAt": "2026-11-26T02:19:40.123Z"
      }
    ]
  }
}
```

### `GET /api/attendance/export?format=xlsx|pdf&moduleId=&date=` - Lecturer

Same filters and ownership rules as above. Returns a file generated on the server:

| `format` | Content-Type                                                        | Generator |
| -------- | ------------------------------------------------------------------- | --------- |
| `xlsx`   | `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` | ExcelJS   |
| `pdf`    | `application/pdf`                                                   | PDFKit    |

`Content-Disposition: attachment; filename="attendance-CIT2004-2026-11-25.xlsx"` (`all-dates` when no date). Reports contain the course code and name, selected date, lecturer, generation time, one row per check-in (student ID, first and last name, check-in time in `APP_TIMEZONE`) and the total attendance count.

Errors: `400 VALIDATION_ERROR` (bad `format`/date), `401`, `403 NOT_YOUR_COURSE`.

## Lecturers

### `POST /api/lecturers` - two-step lecturer registration (Public, rate-limited)

The React form collects step 1 (details) and step 2 (programmes and courses) and submits them together:

```json
{
  "firstName": "Lena",
  "lastName": "Lecturer",
  "email": "lena@staff.example.com",
  "workId": "LEC900",
  "password": "Teaching123",
  "programIds": [1, 2],
  "moduleIds": [12, 40]
}
```

Password: 8–72 characters with at least one letter and one number (hashed with bcrypt). Every module must be offered in the current semester by at least one selected programme. Creates a `LECTURER` account (the role cannot be chosen - a `role` field is rejected) and its `lecturer_modules` rows for the current semester.

`201 { "data": { "user": { ... }, "semester": { ... }, "assignedModuleCount": 2 } }`

Errors: `400 VALIDATION_ERROR`, `400 INVALID_PROGRAM`, `400 MODULE_NOT_OFFERED`, `409 DUPLICATE_WORK_ID`, `409 DUPLICATE_EMAIL`, `409 NO_ACTIVE_SEMESTER`.

### `GET /api/lecturer/courses?scope=current|all` - Lecturer

`current` (default): the lecturer's courses for the current semester, each with its open session (if any) and live attendance count. `all`: every module ever assigned (used by the attendance page filter).

```json
{
  "success": true,
  "data": {
    "semester": { "label": "2026/2027 Semester 1", "...": "..." },
    "courses": [
      {
        "id": 12,
        "code": "CIT2004",
        "name": "Object-Oriented Programming",
        "credits": 4,
        "programs": ["BSc Computing – Computer Science", "BSc Computing – Information Technology"],
        "semester": { "...": "..." },
        "openSession": { "id": 7, "openedAt": "2026-11-26T02:19:40.123Z", "attendanceCount": 3 }
      }
    ]
  }
}
```

### `POST /api/class-sessions` - open a session (Lecturer, CSRF)

```json
{ "moduleId": 12 }
```

The module must be assigned to the lecturer for the **current** semester. `opened_at` is set by PostgreSQL. At most one open session per lecturer + module + semester (also enforced by a partial unique index).

`201`:

```json
{
  "success": true,
  "data": {
    "id": 7,
    "moduleId": 12,
    "module": { "code": "CIT2004", "name": "..." },
    "semesterId": 3,
    "openedAt": "...",
    "closedAt": null,
    "isOpen": true
  }
}
```

Errors: `403 NOT_YOUR_COURSE`, `409 SESSION_ALREADY_OPEN`, `409 NO_ACTIVE_SEMESTER`, `403 CSRF_INVALID`.

### `PATCH /api/class-sessions/:id/close` - close a session (Lecturer, CSRF)

Ownership checks: the session exists (`404 SESSION_NOT_FOUND`), was opened by this lecturer (`403 NOT_YOUR_SESSION`), and its module is still assigned to them for that semester (`403 NOT_YOUR_COURSE`). Then `closed_at = now()` is set only if the session is still open (`409 SESSION_ALREADY_CLOSED` otherwise). Sessions never close automatically.

`200 { "data": { "id": 7, "isOpen": false, "closedAt": "...", "attendanceCount": 23, "...": "..." } }`

## Administrator endpoints

Everything under `/api/admin` requires an **administrator session**, and `POST`/`PATCH`/`DELETE` also require the `X-CSRF-Token` header. Deletes are refused with `409 IN_USE` while other records depend on the row.

| Method | Endpoint                                                    | Body / query                                                                      | Notes                                                                |
| ------ | ----------------------------------------------------------- | --------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| GET    | `/api/admin/overview`                                       |                                                                                   | Counts and current semester                                          |
| GET    | `/api/admin/schools`                                        |                                                                                   | With programme counts                                                |
| POST   | `/api/admin/schools`                                        | `{ code, name }`                                                                  | `409` duplicate code                                                 |
| PATCH  | `/api/admin/schools/:id`                                    | any of `code`, `name`                                                             |                                                                      |
| DELETE | `/api/admin/schools/:id`                                    |                                                                                   | `409` while it has programmes                                        |
| GET    | `/api/admin/programs`                                       |                                                                                   | With module and student counts                                       |
| POST   | `/api/admin/programs`                                       | `{ schoolId, name, major? }`                                                      |                                                                      |
| PATCH  | `/api/admin/programs/:id`                                   | any of the above                                                                  |                                                                      |
| DELETE | `/api/admin/programs/:id`                                   |                                                                                   | `409` while students are registered; programme-module links cascade  |
| GET    | `/api/admin/programs/:id/modules`                           |                                                                                   | Programme-module assignments                                         |
| POST   | `/api/admin/programs/:id/modules`                           | `{ moduleId, level (1–6), semesterSlot ("1"/"2"/"YEAR"/"EITHER"), choiceGroup? }` | `409` if already linked                                              |
| PATCH  | `/api/admin/programs/:id/modules/:moduleId`                 | any of `level`, `semesterSlot`, `choiceGroup`                                     | Empty `choiceGroup` clears it                                        |
| DELETE | `/api/admin/programs/:id/modules/:moduleId`                 |                                                                                   | Module stays in the catalog                                          |
| GET    | `/api/admin/modules?search=`                                |                                                                                   | Each module with the programmes using it                             |
| POST   | `/api/admin/modules`                                        | `{ code, name, credits (int or null) }`                                           | `409` duplicate code                                                 |
| PATCH  | `/api/admin/modules/:id`                                    | any of the above                                                                  |                                                                      |
| DELETE | `/api/admin/modules/:id`                                    |                                                                                   | `409` with enrollments, assignments or sessions                      |
| GET    | `/api/admin/semesters`                                      |                                                                                   | With `isCurrent` flag and usage counts                               |
| POST   | `/api/admin/semesters`                                      | `{ academicYear "2026/2027", term (1/2), startDate, endDate }`                    | `400` end ≤ start; `409 SEMESTER_OVERLAP`; `409` duplicate year+term |
| PATCH  | `/api/admin/semesters/:id`                                  | any of the above                                                                  | Same checks                                                          |
| DELETE | `/api/admin/semesters/:id`                                  |                                                                                   | `409` when in use                                                    |
| GET    | `/api/admin/students?search=`                               |                                                                                   | Search by ID, name or email (max 500 rows)                           |
| GET    | `/api/admin/students/:id`                                   |                                                                                   | Details + enrollments by semester                                    |
| PATCH  | `/api/admin/students/:id`                                   | any of `idNumber`, `firstName`, `lastName`, `email`, `programId`                  | `409` duplicates                                                     |
| DELETE | `/api/admin/students/:id`                                   |                                                                                   | `409` when the student has attendance                                |
| POST   | `/api/admin/students/:id/enrollments`                       | `{ moduleId, semesterId }`                                                        | Either/or rule checked against the student's programme               |
| DELETE | `/api/admin/students/:id/enrollments/:semesterId/:moduleId` |                                                                                   |                                                                      |
| GET    | `/api/admin/lecturers?search=`                              |                                                                                   | Never includes password hashes                                       |
| POST   | `/api/admin/lecturers`                                      | `{ firstName, lastName, email, workId, password }`                                | Creates a `LECTURER`                                                 |
| GET    | `/api/admin/lecturers/:id`                                  |                                                                                   | With course assignments                                              |
| PATCH  | `/api/admin/lecturers/:id`                                  | any of the above; `password` resets it                                            |                                                                      |
| DELETE | `/api/admin/lecturers/:id`                                  |                                                                                   | `409` if they have class sessions                                    |
| POST   | `/api/admin/lecturers/:id/modules`                          | `{ moduleId, semesterId }`                                                        | Lecturer-course assignment                                           |
| DELETE | `/api/admin/lecturers/:id/modules/:semesterId/:moduleId`    |                                                                                   | `409 SESSION_OPEN` while a session for it is open                    |
| GET    | `/api/admin/admins`                                         |                                                                                   | Administrator accounts                                               |
| POST   | `/api/admin/admins`                                         | `{ firstName, lastName, email, workId, password }`                                | Only an authenticated admin can create another admin                 |

Example - add a year-long module to a programme:

```http
POST /api/admin/programs/2/modules
Content-Type: application/json
X-CSRF-Token: <token from login>

{ "moduleId": 55, "level": 4, "semesterSlot": "YEAR" }
```

## Error codes

| Code                                                                                                              | Status | Meaning                                                |
| ----------------------------------------------------------------------------------------------------------------- | ------ | ------------------------------------------------------ |
| `VALIDATION_ERROR`                                                                                                | 400    | Request failed Zod validation (see `errors`)           |
| `INVALID_JSON`                                                                                                    | 400    | Body is not valid JSON                                 |
| `INVALID_PROGRAM`                                                                                                 | 400    | Programme does not exist                               |
| `MODULE_NOT_OFFERED`                                                                                              | 400    | Module not offered by the programme(s) this semester   |
| `EITHER_OR_CONFLICT`                                                                                              | 400    | Two modules from one either/or group                   |
| `INVALID_DATES`                                                                                                   | 400    | Semester end date not after start date                 |
| `UNAUTHENTICATED`                                                                                                 | 401    | No valid session                                       |
| `SESSION_INVALID`                                                                                                 | 401    | Account deleted or role changed since login            |
| `INVALID_CREDENTIALS`                                                                                             | 401    | Wrong email/work ID or password                        |
| `WRONG_LOGIN_PORTAL`                                                                                              | 403    | Correct password, but wrong login system for this role |
| `WRONG_ROLE`                                                                                                      | 403    | Signed in, but this endpoint is for the other role     |
| `NOT_YOUR_COURSE`                                                                                                 | 403    | Lecturer is not assigned to the module                 |
| `NOT_YOUR_SESSION`                                                                                                | 403    | Session was opened by another lecturer                 |
| `NOT_ENROLLED`                                                                                                    | 403    | Student not enrolled in the session's module           |
| `CSRF_INVALID`                                                                                                    | 403    | Missing or wrong `X-CSRF-Token`                        |
| `ORIGIN_NOT_ALLOWED`                                                                                              | 403    | State-changing request from a foreign website          |
| `STUDENT_NOT_FOUND`, `SESSION_NOT_FOUND`, `PROGRAM_NOT_FOUND`, `MODULE_NOT_FOUND`, `NOT_FOUND`, `ROUTE_NOT_FOUND` | 404    |                                                        |
| `ALREADY_CHECKED_IN`                                                                                              | 409    | Duplicate attendance                                   |
| `SESSION_CLOSED`                                                                                                  | 409    | Check-in to a closed session                           |
| `SESSION_ALREADY_OPEN`, `SESSION_ALREADY_CLOSED`                                                                  | 409    |                                                        |
| `NO_ACTIVE_SEMESTER`                                                                                              | 409    | No semester covers today                               |
| `DUPLICATE`, `DUPLICATE_ID_NUMBER`, `DUPLICATE_EMAIL`, `DUPLICATE_WORK_ID`                                        | 409    | Unique value already used                              |
| `SEMESTER_OVERLAP`                                                                                                | 409    | Date range overlaps another semester                   |
| `IN_USE`                                                                                                          | 409    | Record still referenced elsewhere                      |
| `RATE_LIMITED`                                                                                                    | 429    | Too many requests                                      |
| `INTERNAL_ERROR`                                                                                                  | 500    | Unexpected server error (details only in server logs)  |

### Rate limits (per client IP, configurable)

| Endpoints                                                     | Default                                                     |
| ------------------------------------------------------------- | ----------------------------------------------------------- |
| `POST /api/attendance`, `GET /api/students/:id/open-courses`  | 600 requests / 10 min (a kiosk or campus NAT shares one IP) |
| `POST /api/students`, `POST /api/lecturers`                   | 30 requests / 15 min (one counter shared by both)           |
| `POST /api/auth/lecturer/login`, `POST /api/auth/admin/login` | 10 **failed** attempts / 15 min                             |
